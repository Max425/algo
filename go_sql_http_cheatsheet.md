## 🐹 Go

### 🔁 Что такое `recover`
`recover()` — функция, которая используется внутри `defer` для перехвата паники (`panic`) и предотвращения краша программы.

```go
func safe() {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("Поймали панику:", r)
        }
    }()
    panic("ошибка") // без recover программа бы упала
}
```

- Используется для безопасного завершения функции или программы после ошибки.

---

### 🪄 Что такое `defer`
`defer` откладывает выполнение функции до выхода из текущей функции.

- Выполняется **в обратном порядке**.
- Часто используется для освобождения ресурсов (файлы, соединения, мьютексы).

```go
func example() {
    defer fmt.Println("Выполнится последним")
    fmt.Println("Выполнится первым")
}
```

---

### 🧨 Конкурентная запись в `map`
⚠️ В Go **`map` не потокобезопасна**. Конкурентная запись или одновременное чтение и запись вызовет **panic: concurrent map writes**.

✅ Решения:
- Использовать мьютекс:
```go
var mu sync.Mutex
mu.Lock()
m[key] = val
mu.Unlock()
```
- Использовать `sync.Map` — потокобезопасный аналог.

---

### 🗂️ Как сделать множество в Go
Используй `map[Тип]struct{}` — значения не хранятся, только ключи:

```go
set := make(map[string]struct{})
set["apple"] = struct{}{}

if _, exists := set["apple"]; exists {
    fmt.Println("Есть в множестве")
}
```

- Для проверки наличия элемента используем `_`.

### 🌀 Что такое горутина
Горутина — это лёгкий поток выполнения, запускаемый через ключевое слово `go`.

```go
go func() {
    fmt.Println("Выполняется асинхронно")
}()
```

- Планируется и управляется рантаймом Go.
- Очень дешёвая по памяти (~2KB).

---

### ⚙️ `go func` сразу запускает функцию или нет?
Да ✅. При написании `go func() { ... }()` функция **немедленно запускается как горутина**.

### 🔒 Примитивы синхронизации в Go
- `sync.Mutex` — мьютекс для взаимного исключения.
- `sync.RWMutex` — мьютекс с разделением на чтение и запись.
- `sync.WaitGroup` — ожидание завершения горутин.
- `sync.Once` — выполнить блок кода ровно один раз.
- `sync.Cond` — условная переменная (сигналы).
- **Каналы (`chan`)** — синхронизация и передача данных.
- **`sync/atomic`** — атомарные операции над числами (Add, Load, Store, CompareAndSwap).

---

### 📭 Чтение из пустого инициализированного канала
- **Небуферизированный канал**: чтение блокируется, пока кто-то не запишет.
- **Буферизированный канал**: чтение блокируется, если буфер пуст.
- **Закрытый канал**: чтение вернёт нулевое значение типа и `ok=false`.

---

### ⏸️ Как избежать блокировки при чтении из пустого канала
Используй `select` с `default`:

```go
select {
case val := <-ch:
    fmt.Println("Прочитали:", val)
default:
    fmt.Println("Канал пуст — пропускаем")
}
```

- `default` выполнится, если канал пуст, и программа не заблокируется.

## 🗄️ SQL

### 🆕 Оператор для вставки только уникальных строк
PostgreSQL:
```sql
INSERT INTO users (id, name)
VALUES (1, 'Maxim')
ON CONFLICT (id) DO NOTHING;
```

MySQL:
```sql
INSERT IGNORE INTO users (id, name) VALUES (1, 'Maxim');
```

- Альтернативный способ — использовать `SELECT DISTINCT` для уникальности:
```sql
INSERT INTO users (id, name)
SELECT DISTINCT id, name
FROM temp_users;
```

---

### ↪️ Оператор для смещения строк
Пропуск первых N строк:
```sql
SELECT * FROM table
OFFSET 10;
```
- Часто вместе с `LIMIT`:
```sql
SELECT * FROM table
LIMIT 5 OFFSET 10;
```

---

### 📉 Оператор для ограничения количества строк
```sql
SELECT * FROM table
LIMIT 5;
```

---

### 🔗 `JOIN`, который возвращает только строки с совпадениями в обеих таблицах
`INNER JOIN`:
```sql
SELECT *
FROM orders
INNER JOIN customers ON orders.customer_id = customers.id;
```
- Возвращает только те строки, где есть совпадение в обеих таблицах.

## 🌐 HTTP

### 📦 Что есть в HTTP-ответе
1. **Статусная строка**
```
HTTP/1.1 200 OK
```
2. **Заголовки (Headers)**
```
Content-Type: application/json
Content-Length: 123
```
3. **Тело ответа (Body)**
```json
{"message": "ok"}
```

---

### 🛠️ Какие методы идемпотентные
| Метод      | Идемпотентный | Описание                                  |
|------------|---------------|--------------------------------------------|
| **GET**    | ✅ Да          | Получение ресурса                          |
| **HEAD**   | ✅ Да          | Как GET, но без тела                       |
| **PUT**    | ✅ Да          | Полная замена ресурса                      |
| **DELETE** | ✅ Да          | Удаление ресурса                           |
| **OPTIONS**| ✅ Да          | Получение поддерживаемых методов           |
| **PATCH**  | ⚠️ Обычно нет  | Частичное изменение                        |
| **POST**   | ❌ Нет         | Создание ресурса (каждый раз создаёт новый)|
